# 로컬 솔버와 HiGHS 비교

Windows 11 Pro 10.0.26300, Intel Core Ultra 7 255H, Rust 1.100.0에서 동일한 가상 데이터와 릴리스 빌드로 각각 세 번 비교했다. HiGHS 1.16.0은 good_lp 1.15.3을 통해 스레드 한 개로 실행했다. 시간에는 필요한 배치 후보나 모델을 만드는 과정이 포함된다. 두 프로그램의 배치 결과를 동일한 배치 평가기로 확인했다.

| 데이터 | 로컬 솔버 중앙값과 판정 | HiGHS 중앙값과 판정 |
|---|---|---|
| 기준 학과 42분반 / 68배치 단위 | 11.656ms, 68개 배치, 필수 위반 0, 선호 점수 0 | 1.989s, 68개 배치, 필수 위반 0, 선호 점수 0 |
| 스트레스 150분반 / 222배치 단위 | 109.149ms, 222개 배치, 필수 위반 0, 선호 점수 0 | 3.796s, 제한 종료까지 해 미발견 |
| 교원 한 명에게 한 교시에 두 분반을 요구 | 0.050ms, 해 없음 확인, 1개 부분 배치와 필요한 교시 2개·가능 교시 1개 보고 | 1.440ms, 해 없음 확인 |

비교 모델은 기본 학교 규칙을 사용했다. 필수과목 중복은 필수 제약이고 강의실 준비·정리 시간은 0분이다. HiGHS에는 모델 구성 후 3초까지 남은 시간을 넘겼다. 스트레스 데이터에서는 반환까지 걸린 전체 시간이 3초를 넘겼다. 로컬 솔버는 150분반 목표를 충족했고 미배정 원인을 구조화해 반환하므로 앱 코어에서 사용한다.

```powershell
cargo run --release -p auler-engine --example solve --locked
cargo run --release --manifest-path tools/solver-spike/Cargo.toml --locked
```

비교 도구 빌드에는 Visual Studio C++ Build Tools, PATH의 CMake, 그리고 `LIBCLANG_PATH`가 가리키는 libclang이 필요하다. 비교 도구는 별도의 Cargo 작업공간에 있으며 앱 빌드에서 사용하는 의존성에 포함되지 않는다.
