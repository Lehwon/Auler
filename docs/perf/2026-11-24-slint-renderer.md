# 렌더러별 메모리 측정 (2026-11-24)

Slint의 GPU 렌더러(femtovg, OpenGL)와 소프트웨어 렌더러의 메모리를 비교했다. 결과에 따라 소프트웨어 렌더러만 빌드에 넣었다.

## 조건

- PC: Intel Core Ultra 7 255H, RAM 23GB, Intel Arc 140T, Windows 11 Pro (빌드 26300)
- 화면: 2880×1800, 배율 200%, 창 내용 1366×768 (논리 픽셀)
- 빌드: 릴리스(`lto = "thin"`, `codegen-units = 1`), Rust 1.100.0, Slint 1.19.1
- 지표: `tools/measure-memory.ps1`. 앱과 모든 하위 프로세스의 Private Bytes 합계. 실행 8초 후 0.5초 간격 5회 평균
- 화면 상태: 실행 직후 유휴. 스크롤·드래그·장시간 사용은 재지 않았다.
  - 시간표: 그림 6 축소판(5×8 격자, 카드 12개, 미배정·상세 패널)
  - 기준자료 500행: 가상 분반 500행 표(보이는 행만 생성)
  - 빈 화면: 머리말만 있는 화면

## 결과

| 렌더러 | 화면 | 프로세스 수 | Private (MB) | Working Set (MB) |
|---|---|---|---|---|
| GPU (femtovg) | 시간표 | 1 | 98.4 | 189.0 |
| GPU (femtovg) | 기준자료 500행 | 1 | 73.9 | 164.3 |
| 소프트웨어 | 시간표 | 1 | 21.3 | 51.1 |
| 소프트웨어 | 기준자료 500행 | 1 | 21.8 | 40.7 |
| 소프트웨어만 빌드 | 시간표 | 1 | 21.0 | 39.8 |
| 소프트웨어만 빌드 | 기준자료 500행 | 1 | 21.5 | 40.2 |
| 소프트웨어만 빌드 | 빈 화면 | 1 | 20.1 | 38.4 |

실행 파일 크기: 두 렌더러 포함 14.7MB, 소프트웨어 렌더러만 13.7MB.

## 해석

- GPU 렌더러 메모리의 대부분은 그래픽 드라이버 적재 비용이다. 소프트웨어 렌더러는 드라이버를 올리지 않는다.
- 소프트웨어 렌더러만 빌드한 유휴 값(약 21MB)은 기획서의 유휴 후보 목표(100MB 이하)의 약 1/5이다.
- 500행 표를 띄워도 Private 증가는 1MB 미만이다. 보이는 행만 만드는 표가 동작한다.

## 아직 재지 않은 것

- 스크롤, 드래그, 자동 편성, 출력 중의 피크
- 장시간 사용 후 메모리 증가
- 100%, 125%, 150% 배율. 큰 배율일수록 소프트웨어 렌더러의 프레임 버퍼가 커진다.
- 소프트웨어 렌더러의 스크롤·드래그 부드러움(CPU 사용량)
